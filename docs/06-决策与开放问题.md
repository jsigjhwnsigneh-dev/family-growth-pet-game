# 决策与开放问题｜2026-10-08

本文件记录匿名产品事实，不记录任何真实儿童或家庭私有信息。

## 已确认的决定

| 决策编号 | 内容 |
|---|---|
| D01 | 核心目的：让孩子在喜欢的游戏激励下养成生活、学习、锻炼、自理与自主完成的习惯 |
| D02 | 最终产品以**成熟完整宠物游戏为主体（B方案）**；家庭成长系统作为游戏扩展 |
| D03 | 最大化保留原游戏的 UI、美术、动画、家园、物品和游戏经济，优先适配而非重做 |
| D04 | 两名儿童独立进度，平板儿童端 + 双家长手机端，未来考虑儿童手表 |
| D05 | 先前 70 个成长候选 + 7 条家庭规则为初始模板库，**不是任务上限** |
| D06 | 家长或孩子能从库里选择任务加入计划，完成数量和计划完成率都应反映在奖励中 |
| D07 | 任务多不等于无节制高分；需防止重复拆分、难度不合理和超龄负担 |
| D08 | 游戏内部阶段解锁 + 平板其他娱乐应用管控（C方案）均属于最终产品目标 |
| D09 | 宠物不能因普通任务失败受到严重惩罚，基础关爱和照料不能买卖 |
| D10 | 原定东亚软萌画风是方向偏好；不必为统一画风推翻成熟游戏 |
| D11 | 五阶段路线：需求 → 清单 → 找成熟项目 → 补缺 → 整合成品 |
| D12 | GitHub 公开仓库记录项目，保护所有真实家庭隐私 |
| D13 | GitHub 管理进度、Codex 后续调研施工，OpenSpec 视工程阶段实际需要引入 |
| D14 | 阶段1确认产品方向后进入阶段2；阶段2只深化能力归属和验收，不提前选游戏或编写代码 |
| D15 | 游戏原生金币与现实奖励兑换必须有来源/权限边界，具体用一类余额还是分账待选型决定 |

## 未定且影响选择的问题

| 编号 | 待核查事项 | 为什么重要 |
|---|---|---|
| O01 | 成熟宠物游戏哪个真正适合、能否合法复用全部必要素材 | 决定B方案是否省工程量 |
| O02 | 华为平板实际型号与系统控制能力 | 决定如何实现其他娱乐 App 限制 |
| O03 | 适龄任务量、难度权重、完成率奖励封顶 | 防刷分又不压迫儿童 |
| O04 | 奖励兑换预算与游戏经济映射 | 防止冲突、过量奖励或通胀 |
| O05 | 家长手机跨设备提醒与双审冲突处理 | 保证家长不用反复催促/重复审批 |
| O06 | 扩展接入儿童手表的安装权限与运动数据接口 | 仅未来增强，不当作已证实 |
| O07 | 实际部署、远程访问和家庭数据保存地点 | 决定维护/备份/隐私方案 |
| O08 | 选定游戏的年龄适配性、孩子真实兴趣与内容安全 | 决定保留哪些游戏功能 |
| O09 | 游戏本身赚取的金币与任务批准获得的现实奖励权益如何区分 | 防止只刷游戏无限兑换现实奖励 |
| O10 | 选定游戏是否支持跨端审批后安全发奖、掉线补发及误审对账 | 决定B方案究竟需要多大改造量 |

## 不能写成已实现的事情

1. 尚未决定使用哪个游戏，之前发现的 GitHub 项目都只是候选。
2. 游戏概念图是效果示意，不等于可用的原创动画与实际游戏。
3. 目前没有验证华为平板自动锁定/放行其他娱乐 App 的实现方法。
4. 未验证儿童手表可安装自制宠物程序及获取儿童跳绳等运动数据。
5. 未经用户确认，不得把当前需求草案直接解释为授权开始施工。
