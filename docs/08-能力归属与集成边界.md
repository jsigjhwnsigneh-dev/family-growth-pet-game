# 能力归属与集成边界｜第二阶段 V1.0

**状态：可用于选型的责任划分，尚未确定具体开源项目或技术。**

## 一、产品根本约束

我们要的是**成熟完整的宠物游戏为主体（B方案）**。儿童打开的是宠物世界，而不是另一个积分软件。家长可以使用独立的简洁管理后台。为了尽量保留成熟游戏原状，成长模块可以作为独立扩展存在；儿童端通过原游戏的任务入口和游戏奖励与之衔接。

**不等于一定要物理上只有一个程序**：产品体验统一、事实不冲突更重要；不能为了“全写进游戏”而重做原有动画、背包和经济系统。

## 二、五类能力的建议归属

| 能力类别 | 理想责任方 | 要求 | 典型REQ |
|---|---|---|---|
| **G｜完整宠物游戏** | 成熟游戏主体原生 | 宠物形象/动画、养成、游戏币与原生商店、存档、已有家园和长期玩法尽可能原样保留 | 17～22、35、48～49 |
| **T｜家庭成长任务** | 尽量用成熟任务组件，做少量定制 | 可扩展模板库、孩子选任务、周期计划、审批、家长奖励、统计、习惯毕业 | 03～09、12～16、37～43 |
| **I｜任务与游戏连接** | 接口/插件/受控奖励适配 | 经批准的现实任务通过游戏原有奖励机制发放，防重复、防串档、失败可恢复 | 10～11、19、23～25、44～46 |
| **D｜设备和操作系统** | 设备已有合法能力或独立控制层 | 华为平板其他娱乐App管控、必要工具白名单、家长临时解锁 | 26～27、30、51；手表33～34 |
| **O｜统一数据安全与运行** | 现有产品基础/必要共用服务 | 角色、家长协同、备份、权限、授权与升级维护 | 01～02、28～29、31～32、36、47、50、52 |

上表表达的是**责任边界，不是要求安装五款软件**。某款完整游戏可能原生覆盖G和部分T/I，只需极小的外部接入；也可能需要一套独立的成长后台，但绝不能将其视为另一套相互冲突的宠物账本。

## 三、哪些数据应该有唯一权威

| 事实与资产 | 预期权威来源 | 不允许的情况 |
|---|---|---|
| 儿童与家长身份及授权 | 统一的家庭身份关系 | 共用Pad误把孩子A的奖励发给孩子B |
| 现实任务计划、有效期、完成申请和家长批准 | 成长任务系统 | 孩子自己改分值、改分母、自己批准自己的任务 |
| 任务完成率、有效工作量与成长历史 | 成长任务系统（保留计划快照） | 临时删除未完成项目使上周完成率由80%变成100% |
| **游戏原生金币、等级、背包和宠物** | **原游戏的原生存档与规则** | 成长后台再造一套冲突的“游戏金币余额” |
| 游戏奖励发放请求和送达状态 | 唯一标识的连接事件账 | 断网、双家长点击后，游戏收到同一任务三次奖励 |
| 现实奖品的兑换和兑现状态 | 家长授予的现实兑换额度/记录 | 游戏刷小游戏金币无限购买真实物品 |
| 其他娱乐App的解锁与白名单 | 经华为实机验证的设备控制能力 | 仅在网页显示“已解锁”却无法真正限制外部游戏 |

这些是选择候选项目时要核查的**能力**，不是说我们已经找到现成的接口。

## 四、关于金币：一个必须在选型后做出的决定

成熟宠物游戏一般已有赚钱方式，例如小游戏、每日奖励、出售物品；而孩子完成现实任务也要获得游戏金币。如果所有金币都能随意换现实玩具，可能只靠玩游戏就刷到现实奖励，偏离教育目标。

可选路线：

**A｜游戏金币同一余额，现实兑换另有来源验证。** 游戏仍掌管真实游戏金币；只有经过家长批准、来源可核验的额度才可以申请现实奖品。需要游戏已有足够可靠的原生账本或适配能力。

**B｜游戏金币与现实心愿额度分开。** 完成现实任务触发原生游戏金币/经验，同时记入现实奖励可用额度，游戏自己生成的金币只能在游戏内消费。两者是不同的合法权益，必须对孩子展示清楚。

**当前不裁决采用A还是B。** 需要查到具体成熟游戏的原生经济实现后，比较可靠性与最小改造量；不能预先把原游戏金币体系推倒重做。

## 五、最小连接合同（要求，不限定实现技术）

1. 一个现实任务实例对应明确的儿童、计划/规则版本和提交状态。
2. 未经授权批准，不得发出有效游戏奖励；可配置部分安全任务自动确认。
3. 奖励事件有唯一标识，**同一事件重复送达也只能兑现一次**。
4. 游戏离线时请求进入待发状态，重连后能继续，不多发也不丢失。
5. 误批、补记、冲突有追踪与补偿机制，禁止静默修改历史。
6. 游戏升级与家庭系统升级后，奖励映射和角色关系仍然有效。
7. 现实奖励兑换由家长控制，不能凭游戏客户端上报金币数量绕开批准。
8. 允许将新增任务入口嵌入现有游戏交互；不要求为了统一外观而重构全部UI。

## 六、最少改造的优先级

**原生完整保留 → 原厂配置/插件 → 外部适配/少量代码扩展 → 局部修改原源码 → 大量重写（原则上拒绝，另行裁决）**。

第三阶段要根据源码和实测，记录每款候选的**原生保留比例、必须碰的模块、版权与美术费用、升级冲突风险**。不要仅靠仓库Star数、README功能名称或者单张效果图判定“成熟”。

## 七、集成示例

> 宠物游戏内的今日任务 → 孩子实际完成 → 手机待审队列 → 家长批准 → 唯一奖励事件 → 游戏原生金币/宠物变化 → 孩子查看成长进度。
