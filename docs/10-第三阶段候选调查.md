# 第三阶段｜成熟宠物游戏候选调查 V0.1

**日期：2026-10-08｜状态：第三阶段进行中，首轮筛选与重点源码调查已记录；尚未最终选型，不进入产品施工。**

依据：[52项能力](04-功能与验收追踪.md)、[责任边界](08-能力归属与集成边界.md)、[22项验收场景](09-验收场景与反例.md)。产品仍采用 **B：成熟宠物游戏为主体，成长任务/家长审批为扩展**。不能为了项目容易改，就把一个简单演示自动降格选为完整游戏。

## 一、当前判断

**Tamaweb 是本轮最值得继续核验的游戏主体候选，但素材授权尚未过关；Tamagochi / Mori 是较轻量的技术备选，尚不足以认定为满足全部长期游戏体验的成熟主体。**

本轮并未发现已经证明可原样复用、只加一条链接便满足家庭目标的现成产品。发现游戏内已有奖励机制不等于它已具备安全的家长审批接口。我们可望省下大量游戏内容和美术制作，但仍要处理家庭身份、可靠发奖、权限、存档和设备限制。

## 二、调查范围与证据层级

本轮使用公开网页、作者官网、GitHub检索、仓库文件及固定提交检查。中文、英文及日/韩相关检索用于扩展线索；下表只列有明确可核对来源的主要候选，不声称覆盖互联网上所有项目。

- **文档证据**：说明作者声称有什么，不等于本轮独立复现。
- **源码证据**：具体函数/数据结构存在，不等于所有边界安全或目标设备已经通过。
- **运行证据**：必须记录真实进入游戏与操作结果；浏览器试玩也不等于华为Pad实机或孩子使用验收。
- **最终选型证据**：还需资产授权、稳定外部奖励接入、中文体验、目标设备和改造净成本。

没有复制第三方源码/美术到本仓库，没有修改任何候选游戏或用户设备，没有联系作者、注册账号、付费或公开部署游戏。研究环境的源码归档下载因DNS网络失败，**本轮未完成本地构建复现**，不能据此认定上游项目本身不可构建。

## 四、Tamaweb：值得研究，但不能直接采用

### 4.1 可望保留的内容

所读源码确认存在宠物动画定义、游戏任务计数与奖励、宠物/家具/植物/动物存档、导入导出等机制。官网还列出换装、不同成长形态、房间、天气、种植、活动和社交等内容。**源码里有对应机制与官网宣称的全部内容均已试玩，应严格区分。**

固定提交：`9a999b5e8322549c5b2201661d30bdfdf8bbfbdc`。本轮读取的关键文件包括：

- `src/Missions.js`：done、refresh、openRewardsMenu；任务目前针对吃东西、摸宠物、赢小游戏、访问线上区域等**游戏内行为**，不是儿童现实任务审批。
- `src/PetDefinition.js`：idle、moving、eating、blush等逐帧时序及互动表现。
- `src/App.js`：save/load、loadFromJson、getSaveCode/exportSaveCode、游戏货币及外部服务。文件承担很多不同职责，后续需要实际评估适配影响，不能仅凭能找到函数就称“零修改”。

### 4.2 关键授权问题

README和条款将代码与游戏内容列为 **CC BY-NC-SA 4.0**，而同一份使用条款又明确对名称、标识以及第三方项目中的素材使用要求事先许可。

**因此目前无法确认我们可以直接保留全套美术、改造并在公开仓库分发。** 这不是判定一定不能用，而是不能把许可范围含混当作已经通过REQ-32。特别是只在家里使用的私有改造与上传公开仓库/公开演示，是不同的使用情境。

后续需明确：哪些图像/动画/音效属于CC许可，是否含另外授权的第三方资源，非商业家庭改造能否保留素材，公开代码与演示怎样署名/去品牌。**本轮只记录问题，没有发送询问或申请授权。** 如果需大面积重画才能使用，必须重新比较是否仍符合省工程量的B路线。

### 4.3 不只是增加一个任务按钮

1. **双儿童存档**：所读保存/加载逻辑使用固定pet、missions等键。同一游戏有多只宠物不等于支持两个孩子独立账户。需明确隔离的游戏存档与家庭身份映射。
2. **家长审批与安全发奖**：游戏内任务可本地完成/领奖，但本轮未找到可信的双家长审批、唯一奖励收据和跨端补发接口。需接入而非直接相信孩子设备上报。
3. **儿童模式**：源码/官网有线上互动、随机奖励池、遥测、衰老和复活费用等线索。是否能低成本关闭，必须追踪入口和后台调用；不能只隐藏按钮就算安全。
4. **中文与触屏**：所读任务和提示文案包含大量英文。完整汉化、字体、文字尺寸及平板交互均未验证。
5. **备份**：本地导出机制存在，但部分mods/背景数据未包含在导出中，且尚未做恢复演示；不能宣称完整家庭云备份已具备。

## 五、Tamagochi / Mori：改动入口较清楚，不能混淆为大型世界

固定提交：`4ffa9c3de87d58d6b962a4d2fcd12c3fa5250c23`。

实际读取 `src/game/store.ts`，可见care、completeActivity、purchaseKeepsake、toggleKeepsake、exportSave/importSave等状态动作，以及单个本地持久化键。已有照料、游戏奖励和物品购买路径，适合继续评估外接家庭任务的位置。

正式MIT许可证已核查；作者声明宠物/内容原创，这是比含混的素材许可更清楚的起点，但第三方字体与其他依赖仍需单独清单。

**范围必须说准：** README的三个成长形态、四个场景主题、两个小游戏和五段故事，不应被描述为多物种宠物收集、四张探索地图或大型自由建造家园。若最后为了满足体验仍要制作大量新角色与游戏内容，就不符合我们的“以成熟游戏节省主要工程量”的初衷。

其现有本地存档与游戏状态不提供已经验证的家庭账号/家长审批服务。即使代码结构清晰，跨端同步、中文、双儿童和安全发奖也需要补充。**只能作为备选，不能因为MIT和代码简单就直接定为最终主体。**

## 六、华为系统控制的早期结论

[华为官方家长助手文档](https://consumer.huawei.com/cn/support/content/zh-cn06701015/)确认在支持的设备/版本上可设置每个应用的使用限额与停用时间，**没有证明本项目能通过开放API自动联动**。

[Android官方专用设备文档](https://developer.android.com/work/dpc/dedicated-devices)包含lock task应用白名单，但要求完整托管设备管理员；其正式部署流程含恢复出厂设置和注册。不能据此认定家庭华为平板开一个普通权限即可实现，也不能未经授权改为企业托管设备。

两个孩子共用Pad还带来账号与设备权限范围问题，需结合真机选择合理策略。本轮没有进行设备测试。跟踪入口：[Issue #6](https://github.com/jsigjhwnsigneh-dev/family-growth-pet-game/issues/6)。

## 七、在线试玩证据状态

本轮已向独立浏览器发起两个演示的匿名试玩请求：[Tamaweb](https://autosam.github.io/Tamaweb/)与[Tamagochi](https://tamagochi-open-source-game.vercel.app/)。**截至本报告初次提交尚未取得终态试玩报告，故本版不将任何具体互动记为已通过。** 取得可用结果后只追加真实观察，不以官网宣传替代试玩。

即使试玩成功，也只说明当时托管演示在该浏览器的有限操作表现。它不证明固定提交可本地重建、不证明华为兼容、不证明长期稳定、不代表儿童已经喜欢。

## 八、下一步及阶段退出条件

优先核查Tamaweb的素材可复用范围、双存档隔离、奖励发放与恢复的最小接入口；保留Mori作为不同规模对照。不因暂未解决主候选授权就悄悄换成从零造游戏。

第三阶段正式收口仍须：游戏可运行证据；代码与素材许可明确；家庭成长连接的实际改造范围与风险；目标设备验证；候选对比与用户批准。**目前这些条件没有全部满足，Issue #3继续开放。**
